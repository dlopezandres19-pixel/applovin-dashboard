Gross Adds vs. Churn
Between consecutive weekly runs · BuiltWith live + expired counts · Starts with the automated weekly runs
What this shows: BuiltWith keeps two counts — live sites (pixel detected now) and expired sites (pixel detected in the past, no longer found). Each bar compares two weekly runs. Gross adds = increase in live + expired, i.e. websites on which the pixel was detected for the first time. Churned = increase in expired, i.e. websites that dropped the pixel, net of websites that re-installed it (so true churn can be somewhat higher). By construction, net change in live sites = gross adds − churned. Churn % = churned ÷ live sites at the previous run. A temporary crawler miss can show up as churn and reverse the following week. Only BuiltWith's current snapshot reports expired sites, so this series is built from the weekly runs forward and is dated by run (it is not lagged like the chart above).

📊 Data Sources & Methodology
①
What is counted: websites where BuiltWith detects AppLovin's tracking pixel (Axon). A site with the pixel is not necessarily an active, paying advertiser — treat as a leading indicator of merchant adoption.
②
Live vs. redirects: BuiltWith also lists domains that only redirect to a live site; these are excluded. Third-party trackers quoting larger totals typically include them. Absolute levels differ across trackers — the trend is the signal.
③
Publication lag: BuiltWith publishes each week roughly 2–3 weeks later. Unpublished weeks are left out (not shown as 0% growth) and filled in automatically by later runs.
④
Restatements: BuiltWith re-crawls and can revise past weeks. The series always shows the latest figures; revisions are logged in the Data Quality table.
⑤
Churn & traffic tiers: "Expired" sites are only reported for BuiltWith's current snapshot, so gross adds and churn are built run-to-run from the weekly runs forward; churn is net of sites that return from expired to live. Top 1M / 100k / 10k use BuiltWith's periodically refreshed traffic-rank list — a one-week step across all tiers (e.g. late Sep-2026) can reflect a list refresh rather than new large merchants.
⑥
Valuation: Capital IQ NTM P/E (SP_PE_FWD) and NTM EV/EBITDA (SP_TEV_EBITDA_FWD), monthly end-of-period; the latest point is the workbook's pricing date. "NM" (not meaningful) values are left blank. Updated manually from APP_Dashboard.xlsx. APP share price on the pixel chart: daily close (Yahoo Finance / Nasdaq), last close on or before each Saturday; refreshed on every run.
